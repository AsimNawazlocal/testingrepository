Date basis: single build/audit pass, this session

================================================================================
1. PROJECT / STACK
================================================================================
Static HTML site, no build step, no framework, no package.json. 34 pages total
(homepage + 33 files under /pages/). Served for testing via a plain local HTTP
server (python3 -m http.server) from the site root; the production deployment
target uses clean URLs (e.g. /water-heater-repair/) resolved by the hosting
platform's own routing, so tests below hit the equivalent file paths directly
(e.g. /pages/water-heater-repair.html) rather than the clean URLs, which a local
static file server cannot resolve without a routing layer. This does not affect
the validity of the rendering/layout/interaction results, which are per-file.

4. HORIZONTAL OVERFLOW
================================================================================
CONFIRMED AND FIXED (1 issue, site-wide root cause):
All 34 pages' shared footer (plus a duplicate occurrence in contact.html's
".infocard" and a second body-text occurrence in privacy.html) contained the
unwrapped email address "contact@sandyutplumbingexperts.com" as a mailto link
with no break opportunity. At 320px this overflowed the viewport by 9px (most
pages), 19px (privacy.html, extra body-text occurrence), and 29px
(contact.html, extra .infocard occurrence) — confirmed by direct DOM
measurement (`document.documentElement.scrollWidth` vs `clientWidth`) and by
screenshot. See Section 9 for the fix and Section 11 for before/after evidence.

After the fix: a full regression sweep of all 34 pages at 7 widths (320, 375,
414, 768, 1024, 1440, 1920px — 238 checks) found 0 pages with horizontal
overflow beyond the standard ~15px scrollbar/rounding tolerance, and a
dedicated 320px-only resweep of all 34 pages found 0px of overflow on every
page (exact match, not just within tolerance).

No other horizontal overflow was found anywhere else on the site at any tested
viewport.

================================================================================
5. KNOWN NETWORK FAILURE PATTERNS — TARGETED RESULTS
================================================================================
A. Footer column overflow on narrow mobile — NOT PRESENT / PASS.
   This site's footer has only 3 simple stacked blocks (brand+contact, Hours,
   Serving) in a single responsive column, not a multi-column Services/Company
   link grid. It stacks cleanly at 320/375/390/414px (screenshot
   shot_footer_320.png) with no overflow once the mailto fix (Section 4) was
   applied. Every link remains reachable.

B. Tablet desktop-navigation cutoff at 768px — NOT PRESENT / PASS.
   This site's interior-page header nav (Home/Services/Areas/Cost/FAQs/Contact)
   uses `flex-wrap:wrap` with no fixed widths, so at 768px the row wraps onto
   its own line beneath the brand block rather than clipping (screenshot
   shot_header_768.png). The desktop call-to-action button is deliberately
   hidden below 780px and replaced by a fixed bottom call bar — confirmed
   exactly one of the two is visible at every one of 10 viewports across 5
   representative pages (50 checks, 0 failures) with no brand-text/CTA overlap.

C. Header brand/location text clipping — NOT PRESENT / PASS.
   Brand name ("Sandy UT Plumbing Experts") and location label ("Sandy, Utah")
   were measured against the header's right edge at every tested width on 11
   pages; 0 instances of the brand block overflowing the header or overlapping
   the call button/nav links.

D. Mobile hamburger and dropdown failures — NOT APPLICABLE, disclosed rather
   than marked Pass. This site has no hamburger icon, drawer, overlay, or
   dropdown component anywhere in its markup or CSS (confirmed by full-site
   search). Navigation on mobile/tablet is the same static flex-wrap nav bar
   used at every width (tested and working, see B above), paired with a fixed
   bottom call bar. There is nothing matching this pattern to test.

E. False broken-image flags — ONE FALSE POSITIVE CAUGHT AND DISMISSED. An
   initial automated sweep using a reused browser page across sequential
   page.goto() calls logged 5 "requestfailed" network events, apparently
   attached to the wrong route due to an in-flight request from the previously
   loaded page bleeding into the next iteration's event log (a test-harness
   artifact, not a lazy-loading issue — these are new-build photos without
   `loading="lazy"` complications beyond standard lazy attributes already used
   correctly). A clean, isolated re-test (fresh browser page per route, full
   page scroll to settle any lazy loading, then checking `img.naturalWidth`)
   found 0 actually-broken images on all 6 affected routes and, extended to a
   full-site sweep, 0 broken images across all 34 pages. Recorded as a dismissed
   false positive with the evidence that disproved it, per Ground Rule 2.

================================================================================
Homepage FAQ mini-accordion (native <details>/<summary>, 5 instances): tested
programmatically — starts closed, opens on click, uses the browser's native
toggle behavior (no custom JS required, so it is inherently keyboard-
accessible and has no event-handler/ID-collision risk). Pass.

Homepage elevation-pressure slider (custom range input + JS): tested by
dispatching an input event at a sample value (500) and reading back all four

faqs.html's own FAQ list uses static, always-visible ".faqitem" blocks, not a
collapsible accordion — there is nothing to toggle-test there; this is a
content/design choice (all answers visible by default), not a broken

Mobile/tablet hamburger menu tests, dropdown tests, drawer scroll-lock tests,
escape-key tests, and backdrop-click tests: NOT APPLICABLE — see Pattern D in
Section 5. No such component exists on this site.

Inline text links vs. button styling: sampled 7 inline body-text links on a
representative page; 0 were styled as block/inline-block buttons with a
background fill (the conflict this check looks for). CTA buttons (.call,
.btn, .bar) remain visually and semantically distinct from inline links.

Forms: none exist on this site by design (confirmed in the footer's own legal
text: "No enquiry form is used or collected by this page"). Not applicable.

Internal links: 0 broken, out of every href on every one of the 34 pages,

Orphaned pages (informational finding, not a rendering defect): /about/ and

9. FIX APPLIED (ROOT CAUSE)
================================================================================
Added one scoped CSS rule to all 34 pages' existing inline <style> blocks:
  a[href^="mailto:"]{overflow-wrap:break-word;word-break:break-word}
This targets only mailto links (the actual source of the long unbreakable
string) and does not touch any other link, button, or CTA styling anywhere on
the site — chosen deliberately over a broader `a{...}` rule to avoid any risk
of unintended visual change to nav links or CTA buttons elsewhere. Applied
identically across all 34 pages since the footer (and its mailto link) is a
literally-duplicated shared component, not a single template file.
